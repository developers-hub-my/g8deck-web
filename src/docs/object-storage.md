**Storage** in the sidebar holds everywhere your objects live: storage G8Deck
runs for you, and buckets you already own somewhere else.

![The Storage page before anything is added: run it here, or bring your own bucket](/docs/object-storage/storage.webp)

## Add storage

**Add storage** has three modes:

| Mode                            | What G8Deck does                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| **Set up a new storage server** | Installs the Garage daemon on a server you have set up, configures it and opens its port |
| **Adopt one that already runs** | Records a Garage that already runs and changes nothing on the machine                    |
| **Connect an existing bucket**  | Keeps a credential for a bucket you own elsewhere; your provider keeps the bucket        |

![Add storage: the three modes, the server picker and the redundancy choice](/docs/object-storage/new-storage-server.webp)

### A storage server

| Field                               | Notes                                                                                                                                                            |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Redundancy**                      | **One copy** (a disk failure loses every bucket on it) or **Three copies** (three or more servers, each object on three of them). **It cannot be changed later** |
| **S3 API port**, **Listen address** |                                                                                                                                                                  |
| **Domain (optional)**               |                                                                                                                                                                  |
| **Allowed networks**                | Required — internal networks only, never open by default                                                                                                         |
| **Enable TLS**                      | A Let's Encrypt certificate, which needs the domain                                                                                                              |

A storage server's page has **Buckets**, **Access keys**, **Nodes**,
**Connection**, **Backups** and **Setup log**:

- **Buckets** follow S3's naming rule — 3 to 63 characters — and cannot be
  renamed. A deleted name stays reserved. G8Deck will not empty a bucket for
  you: deleting one that still holds objects is refused by the daemon. Buckets
  can carry a quota.
- **Access keys** are generated by the daemon. You can reveal one (audited), copy
  a ready Laravel `.env` block, rotate it, or delete it — a deleted secret cannot
  be recovered.
- **Grants** give one key one level on one bucket — **Read only**, **Read &
  write** or **Owner** — and a new grant replaces the old one.
- **Nodes** add or remove cluster members. Removing one makes Garage move its
  copies onto the rest; removal is refused if it would leave fewer nodes than
  the redundancy needs.

The bucket page browses objects — details and download only, no upload or
delete — for people who hold the reveal permission. Everyone else is told: _You
can see this bucket, not what is inside it._

### A bucket you already own

Providers: **Amazon S3**, **Cloudflare R2**, **Wasabi**, **DigitalOcean
Spaces**, **Garage**, **Ceph RGW** and **Other S3-compatible**. Give it a name,
endpoint, **region** (required — it is recorded as a data-residency fact),
bucket, optional prefix, path-style addressing if your provider needs it, and
the access key. **Saving runs a write test** against the bucket.

## Attach storage to an application

Open the application's **Storage** tab and choose **Attach storage**. An
application writes to **exactly one** source, per environment:

- **A storage server** — G8Deck creates a bucket, an access key and a
  read-write grant, named from the deployment and the application.
- **A bucket you already own** — G8Deck creates nothing and uses that bucket.

![Attaching object storage from an application's Storage tab](/docs/object-storage/attach-storage.webp)

The S3 settings are written into the application's environment and apply on the
next deploy, and that deploy waits until the bucket and key are actually active.
Attaching the same source again reuses the same bucket and key.

**Changing to a different source** needs you to tick _I understand the files
already in this bucket stay there, are not copied across, and stop being
served_. Nothing is deleted and nothing is copied: the old bucket keeps every
object, its key and grant survive, and the application simply stops using it.

**Detach** removes the link and the S3 environment variables from the next
deploy. **It deletes no bucket and no data.** It is still disruptive: an
application that writes uploads keeps working until it is redeployed, and fails
after.

## Delete

| Deleting               | What happens                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| **A storage server**   | The record goes. The daemon keeps running on every node and no object is deleted — it does not stop the bill |
| **A connected bucket** | The credential goes. The bucket at your provider and everything in it is untouched — and still billing       |

## From an AI client

`attach-workload-storage` and `detach-workload-storage` on the [ops
server](/docs/mcp/ops) do the same as the Storage tab; moving to a different
source there needs `leave_existing_objects_behind: true`, which says out loud
what the checkbox says. Bucket and cluster tools are on the [platform
server](/docs/mcp/platform).
